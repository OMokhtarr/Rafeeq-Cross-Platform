# Feelings — Duas & Verses by How You Feel

**Date:** 2026-11-07
**Branch:** `feelings-duas`
**Status:** Design approved in chat; awaiting spec review

## Goal

The user picks how they feel right now (sad, anxious, angry, …) and sees Quran
verses and authenticated duas for that feeling. Inspired by a mood-picker in
another app (emoji face + feeling name list), adapted to Rafeeq's card-grid
patterns.

## Decisions (from brainstorming)

| Topic | Decision |
|---|---|
| Entry point | New card on the **More** page (between Tracker and Account), not a bottom-nav tab |
| Content source | Claude drafts, owner verifies before merge. Duas reuse `azkarData.ts` (al-Albani's *Jami' Sahih al-Adhkar*) wherever possible; new duas carry a hadith source |
| Feelings | Focused list of 12 (below). Curiosity, studying dropped; near-duplicates merged |
| Translation | **Arabic only** for verse/dua text (same as Azkar). UI chrome (title, feeling names, section headings) is bilingual via `strings.ts` |
| Layout | Feeling grid → per-feeling detail page |
| Icons | **System Unicode emoji** (no bundled assets) |
| Verse text | Bundled, **generated by a script** from `api.quran.com` — never hand-typed |
| Data | Local, static, bundled. No user state, no network at runtime |

## Content rules

1. Every dua has a source. Reused duas inherit the source already in `azkarData.ts`.
2. No hadith graded weak by al-Albani. Explicitly excluded: «اللهم ألهمني رشدي…»
   and «اللهم ما أصبح بي من نعمة…».
3. Verse text and mushaf page come only from the generator output.
4. Each feeling has ≥ 1 verse and ≥ 1 dua (enforced by test); target 2–4 of each.

## Architecture

### Files

| File | Role |
|---|---|
| `src/data/feelingsData.ts` | Hand-authored: the 12 feelings, verse refs, dua entries |
| `src/data/feelingsVerses.generated.ts` | Script output: `Record<verseKey, { text, page }>` |
| `scripts/generate-feeling-verses.mjs` | Reads refs from `feelingsData.ts`, fetches from `api.quran.com`, writes the generated file |
| `src/app/features/feelings/Feelings.tsx` | Grid + detail page (one component, two routes — same pattern as `Azkar.tsx`) |
| `src/app/features/feelings/Feelings.css` | Page styles |
| `src/app/features/feelings/feelingsContent.ts` | Pure resolver: feeling → `{ verses: ResolvedVerse[], duas: ResolvedDua[] }` |
| `src/app/features/feelings/__tests__/feelingsContent.test.ts` | Data-integrity + resolver tests |
| `src/App.tsx` | Routes `/feelings`, `/feelings/:feelingId` |
| `src/app/features/more/More.tsx` | New `feelings` entry + smiley line icon |
| `src/app/core/i18n/strings.ts` | `more.feelings` + a `feelings` block (title, prompt, section headings, feeling names, "open in mushaf") in both languages |

### Data shapes

```ts
// feelingsData.ts
export type FeelingDua =
  | { categoryId: string; zikrId: string }                  // reuse from azkarData
  | { text: string; source: string; note?: string };        // new, sourced

export interface Feeling {
  id: string;            // url slug, e.g. "weak-faith"
  emoji: string;         // system emoji
  titleAr: string;
  titleEn: string;
  verses: string[];      // "13:28" or a range in one surah "94:5-6"
  duas: FeelingDua[];
}
```

Zikr ids are **not globally unique** in `azkarData.ts` (`mo-1` and `mo-9` repeat
across categories), so reuse references are always the `(categoryId, zikrId)` pair.

```ts
// feelingsVerses.generated.ts  — DO NOT EDIT, produced by the script
export const FEELING_VERSES: Record<string, { text: string; page: number }> = {
  "13:28": { text: "…", page: 252 },
};
```

Ranges are expanded to single keys in the generated map; the resolver joins them.

### Resolver (`feelingsContent.ts`)

- `getFeeling(id)` → `Feeling | undefined`.
- `resolveVerses(feeling)` → `{ ref, surah, ayahFrom, ayahTo, text, page, firstKey }[]`.
  `text` joins each ayah's text followed by an end-of-ayah mark with Arabic-Indic
  number (`﴿…﴾` wraps the whole passage in the UI). Surah name via
  `getSurahNameArabic` from `metadata.service.ts`.
- `resolveDuas(feeling)` → `{ text, source, note? }[]`, looking up reuse entries
  in `azkarData`.
- Pure functions, no React — that's what the tests target.

### Generator script

`node scripts/generate-feeling-verses.mjs`

- Imports nothing from TS: parses verse refs out of `feelingsData.ts` with a regex
  over the `verses: [...]` arrays (keeps the script dependency-free, like
  `build-quran-corpus.mjs`).
- For each key: `GET https://api.quran.com/api/v4/verses/by_key/{key}?fields=text_uthmani`
  → `verse.text_uthmani`, `verse.page_number`. Public endpoint, no auth.
- Sequential with a small delay; fails loudly (non-zero exit) on any non-200 or
  missing field — never writes a partial file.
- Writes keys sorted, with a header comment naming the script and the source.
- Run once now; re-run whenever `feelingsData.ts` verse refs change. The test
  catches a forgotten re-run.

### UI

**Grid (`/feelings`)**
- Title «كيف تشعر الآن؟» / "How are you feeling?".
- 3-column grid of cards: large emoji (~2.25rem) above the feeling name.
  Reuses the More card look (surface, radius, border tokens). Tap → `history.push`.
- `BottomNavBar active="more" fixed`.

**Detail (`/feelings/:feelingId`)**
- Header: back button + emoji + feeling name.
- **آيات / Verses** section: each card shows the passage in `var(--font-arabic)`
  wrapped in ﴿ ﴾, then «سورة {name} · {ayah or range}». Tapping the card opens
  the mushaf at that verse: `history.push(\`/viewer?page=${page}&v=${firstKey}\`)`
  (same deep link `SearchResults` uses).
- **أدعية / Duas** section: Arabic text, optional `note`, source line —
  visually matching `.azkar-item` (no counter / favourite / audio in v1).
- Unknown `feelingId` → redirect to `/feelings`.

**Rules** (CLAUDE.md): containers capped at `var(--max-width-mobile, 600px)` with
`margin: 0 auto`; scrolling container has
`padding-bottom: calc(var(--bottom-nav-height) + var(--space-6))`; no scrollbar
styling; colours follow Unified Controls (green only as fills, gold for
text/borders). Direction from `useLang().isRTL` for chrome; Arabic text blocks
always `dir="rtl"`.

**Navigation:** `/feelings` and `/feelings/:id` are pushed sub-pages of More and
must **not** be added to `ROOT_TAB_PATHS` — hardware back returns to More (grid)
and to the grid (detail).

## Error handling

There is no runtime I/O, so the only failure modes are bad data, and those are
caught at test time rather than handled at runtime:

- Missing generated verse → test fails (and the resolver throws in dev).
- Missing `(categoryId, zikrId)` → test fails.
- Unknown feeling id in URL → redirect to grid.

## Testing

`feelingsContent.test.ts` (run with
`CI=true npx react-scripts test --watchAll=false --testPathPattern feelings`):

1. Exactly the 12 ids, unique, URL-safe.
2. Every feeling has ≥ 1 verse and ≥ 1 dua.
3. Every verse ref parses, stays inside one surah, `from ≤ to`, and every
   expanded key exists in `FEELING_VERSES` with non-empty text and page 1–604.
4. Every reuse dua resolves to an existing `azkarData` entry.
5. Every inline dua has non-empty `text` and `source`.
6. `resolveVerses` on a range joins ayat in order with the right surah name.

No component tests in v1; the UI is verified on device by the owner.
