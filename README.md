# Rafeeq رفيق

A cross-platform Quran quiz and viewer app built with React, Ionic, and Capacitor. One codebase runs on **Web**, **iOS**, and **Android**.

## Tech Stack

| Layer | Technology |
|---|---|
| UI Framework | [Ionic React 7](https://ionicframework.com/) + React 18 |
| Language | TypeScript 4.9 |
| Cross-Platform Bridge | [Capacitor 8](https://capacitorjs.com/) |
| Routing | React Router 5 via `IonReactRouter` |
| State | React Context API (no Redux) |
| Local Storage | IndexedDB (web) + Capacitor Preferences (native) |
| Quran Data | [`@quranjs/api`](https://github.com/quranjs/api) SDK + bundled JSON seed |
| Build Tool | Create React App (react-scripts 5) |
| Testing | Jest (unit) + Playwright (E2E) |
| Speech-to-text (recite mode) | Deepgram or Soniox, streamed live; keys issued by the token broker |
| Subscriptions (Rafeeq Pro) | [RevenueCat](https://www.revenuecat.com/) Capacitor SDK + Paywall / Customer Center UI |
| Token broker | Cloudflare Worker in `token-broker/` |

## How the App Works

### Startup & Data Seeding

On first launch the app seeds IndexedDB from a bundled `quran-text.json` file containing all 6,236 verses. This makes the app work fully **offline** after the first open. Fonts (QPC V4 Tajweed) are downloaded once from jsDelivr and cached in IndexedDB as blobs, so all 604 Quran pages render correctly without a network connection.

### Global State (Context API)

Five providers wrap the entire app in `App.tsx`:

| Context | What it manages |
|---|---|
| `ThemeContext` | Light/dark theme, persisted to localStorage |
| `LanguageContext` | Arabic/English UI language + RTL/LTR direction |
| `VerseVisibilityContext` | Which verse texts are hidden (used by quiz modes) |
| `PlaybackContext` | Audio queue, current reciter, playback controls |
| `SubscriptionContext` | Rafeeq Pro state from RevenueCat, Paywall, Customer Center |

### Navigation

React Router 5 routes are defined in `App.tsx`. A persistent `BottomNavBar` gives access to the six main sections: **Home**, **Quran**, **Quiz**, **Azkar**, **Hifz**, and **More**.

Main routes:

```
/                                            → Home
/viewer                                      → Quran page viewer
/surah-juz                                   → Surah / Juz picker
/search  →  /search/results                  → Search
/azkar  →  /azkar/:categoryId                → Azkar (daily remembrances)
/quiz-list                                   → Quiz selection
/akmel-alayah-setup  →  /akmel-alayah        → "Complete the verse" quiz
/mutashabihat-setup  →  /mutashabihat-test   → "Similar verses" quiz
/akmel-alnehayat-setup  →  /akmel-alnehayat  → "Beginning to ending" quiz
/hifz                                        → Memorisation plan
/more                                        → More tab
/prayer-times                                → Prayer times, Qibla, alarms
/tracker                                     → Worship tracker
/account                                     → Streaks, notes, subscription & app info
/bookmarks                                   → Saved verses
/settings                                    → App-wide settings
/playback                                    → Reciter & playback settings
/tafsir-settings                             → Tafsir sources
```

### Recite Mode and Rafeeq Pro

Recite mode listens through the microphone, streams the audio live to the
speech engine chosen in Settings (Deepgram or Soniox), and follows the
recitation word by word, marking mistakes. The engines' keys never ship in
the app: the token broker in `token-broker/` hands out short-lived tokens.

Recite mode is the paid **Rafeeq Pro** feature. RevenueCat holds the
subscription (anonymous app-user id, no login); the app shows RevenueCat's
Paywall and Customer Center. It ships behind two switches: the app build
flag `REACT_APP_PRO_GATE=on` and the Worker's `REQUIRE_PRO = "true"`.
Setup and launch order are in `PLAY-CONSOLE-PREP.md` §9.

### Audio Playback

`PlaybackContext` + the `usePlaybackQueue` hook manage verse-by-verse recitation. Audio files are downloaded as MP3 blobs, stored in IndexedDB, and served locally on subsequent plays. Over 200 reciters are supported.

### Local User Data

The app has no accounts and no sign-in. Notes and bookmarks live in `notes.service.ts`, the Hifz streak in `hifz.service.ts`, and the quiz streak in `quiz-streak.service.ts` — all backed by local storage on the device.

Since there is no server, `backup.service.ts` provides the cross-device path: **Account → Backup** exports every user-created store to a JSON file (content caches are excluded) and restores it on another device. The Hifz stores are dual-written to localStorage *and* IndexedDB/filesystem, so backup reads and writes them through the async loaders.

## Running Locally

### Prerequisites

- Node.js 22+ (`engines` in `package.json`)
- npm 10+

### Environment

Copy `.env.example` to `.env.local` and fill it in — at least
`REACT_APP_TOKEN_BROKER_URL` and `REACT_APP_QF_CLIENT_ID`. Each variable is
explained in the file.

### Web (browser)

```bash
npm install
npm start
# Opens at http://localhost:3000
```

## Building for Each Platform

### Web production build

```bash
npm run build
# Output → /build
```

### iOS

> Requires macOS with Xcode and CocoaPods. There is no `ios/` project in the
> repo yet — create it once on a Mac with `npx cap add ios`, then add the
> microphone permission text and `REACT_APP_REVENUECAT_IOS_KEY`.

```bash
npm run ios:sync    # builds web assets and syncs to the ios/ Xcode project
npm run ios:open    # opens Xcode — run on simulator or device from there
```

Or run directly on a connected device/simulator:

```bash
npm run ios:run
```

### Android

> Requires Android Studio with the Android SDK.

```bash
npm run android:sync   # builds web assets and syncs to the android/ Gradle project
npm run android:open   # opens Android Studio
```

Or build directly (Windows; uses Android Studio's bundled JDK):

```bash
npm run android:build  # debug APK + release AAB
# → android/app/build/outputs/apk/debug/Rafeeq-<versionName>-debug.apk
# → android/app/build/outputs/bundle/release/Rafeeq-<versionName>-release.aab
```

Run `npx cap sync android` (included in `android:sync`) after adding or
updating any Capacitor plugin — a plugin missing from the Gradle files stops
every plugin after it from loading.

There is no CI: builds are made locally.

## Key Concepts

### Offline-first

Quran text, fonts, tafsir, and audio are cached locally. The app is usable without internet after the first launch; recite mode and content sync need a connection.

### Platform Detection

Platform-specific behaviour (haptics, status bar, store billing, native audio) is gated on `Capacitor.getPlatform()` (`"web"`, `"ios"`, or `"android"`).

### IndexedDB Schema (v9)

| Store | Contents |
|---|---|
| `verses` | All 6,236 Quran verses (seeded at startup) |
| `pages` | API-fetched verse batches per page |
| `fonts` | QPC V4 Tajweed font blobs |
| `audio` | Recitation audio blobs |
| `hifz` | Hifz plan, best plan, reading session |
| `content_sync` | Synced content rows (tafsir and other resources) |
| `sync_meta` | Content sync token and tracked resources |
| `meta` | Migration flags |

### Capacitor App ID

`com.rafeeq.quranquiz` — used as the iOS bundle ID and Android application ID.
